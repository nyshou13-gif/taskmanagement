# TaskBoard 要件定義書

## 1. 概要
Trello風のシンプルなタスク管理アプリ「TaskBoard」。「未着手」「作業中」「完了」の3つのカラムにタスクカードを並べ、ドラッグ&ドロップで進捗を管理する。
各タスクにはタイトル・説明・優先度・期限を設定でき、カラム単位で優先度順・期限順に並べ替えられる。それ以外の並び順はドラッグ&ドロップで自由に決められる。
まずは最小機能（MVP）で動くものを作り、後から機能を拡張していく。

## 2. スコープ（MVP）

### 対象
- フロントエンド（SPA）とバックエンドAPIで構成し、データはサーバー側のDB（PostgreSQL）に永続化する
- 1ユーザー・1ボードを前提とする
- カラムは「未着手」「作業中」「完了」の3つで固定する

### 対象外（今回はやらない）
- ユーザー認証・ログイン
- 複数ボードの管理
- カラムの追加・削除・名称変更
- 複数人での同時編集・共有

## 3. 機能要件

MVPで実装する機能はF1〜F6（タスクの作成・編集・削除、DnDによる移動・自由な並び替え、優先度順・期限順ソート、データ永続化）。
詳細は [機能一覧](features.md) を参照。

並び替えはTrelloと同様にDnDで自由に行えることを基本とし、優先度順・期限順ボタンは押した時点で1回だけ並べ直す補助機能とする（ソート状態は固定されず、その後もDnDで自由に並び替えられる）。

## 4. 非機能要件

### 対応環境
- 対応ブラウザ: Google Chrome / Microsoft Edge の最新版
- 画面サイズ: PCデスクトップ画面（1280px以上）を優先。レスポンシブ対応は必須としない
- OS: Windows / macOS の主要バージョン

### 性能・容量
- カラム数は3固定、タスク数は1カラムあたり最大50程度を想定した個人利用規模
- 操作（作成・削除・編集・DnD・ソート）に対する画面反映は体感1秒以内（フロントエンド〜バックエンドAPI間の通信を含む）
- DBのデータ量について、個人利用規模である前提から特別な上限は設けない

### セキュリティ
- フロントエンド・バックエンド間はローカル環境内の通信を想定し、外部公開は行わない
- タスクのタイトル・説明等の入力値は、画面表示前のエスケープに加え、バックエンドAPI側でもバリデーション（SQLインジェクション対策としてプレースホルダ/パラメータ化クエリを使用）を行う
- クレジットカード番号やパスワードなど機密情報の入力・保存は想定しない（利用者への注意喚起をREADME等に記載）
- ユーザー認証は対象外のため、APIは誰でもアクセス可能な前提とする（本番公開する場合は認証の追加が必須）

### アクセシビリティ・保守性
- 主要な操作（タスクの作成・編集・削除）はキーボード操作でも実行可能とする（DnDによる移動・並び替えはマウス操作を基本とし、キーボード代替は今後の拡張候補とする）
- コンポーネント単位で機能を分割し、拡張候補（9章参照）に対応しやすい構成とする

## 5. データモデル

COLUMN - TASK の2階層構成。カラムは「未着手」「作業中」「完了」の3件を固定で持ち、タスクは優先度（高・中・低）・期限・説明などを持つ。DBはPostgreSQLを使用する。
ER図・テーブル定義・API仕様の詳細は [データベース設計](database.md) を参照。

## 6. 画面仕様

画面はボード画面の1つのみで、画面遷移は発生せず、タスク作成／編集モーダルと削除確認ダイアログで完結する。
画面イメージ・モーダルの項目・バリデーション/エラー表示の詳細は [画面設計](screens.md) を参照。
画面のモック（ブラウザで開いて確認可能）は [mockup/index.html](../mockup/index.html) にある。

## 7. ユースケース（操作シナリオ）

### UC1: タスクを作成して進捗を管理する
1. 利用者はボード画面を開く（初回はタスクが0件の状態で、「未着手」「作業中」「完了」の3カラムが表示される）
2. 「未着手」カラムの「＋タスク追加」をクリックし、作成モーダルでタイトル（必須）・説明・優先度・期限を入力して「保存」する
3. 作成したタスクが「未着手」カラムの末尾に表示される
4. タスクの進捗に応じて、タスクカードを「未着手」から「作業中」、「完了」へドラッグ&ドロップで移動する
5. ブラウザを閉じて再度開いても、直前の状態が復元されていることを確認する

### UC2: タスクの内容を修正する
1. 利用者はボード画面上の対象タスクカードをクリックする
2. 編集モーダルが開き、現在のタイトル・説明・優先度・期限が表示される
3. 内容を修正し、「保存」ボタンをクリックする
4. モーダルが閉じ、ボード上のタスクカード表示が更新される

### UC3: 不要になったタスクを削除する
1. 利用者は削除したいタスクカードをクリックして編集モーダルを開き、「削除」ボタンをクリックする
2. 削除確認ダイアログが表示され、対象タスクのタイトルと「この操作は取り消せません。」という注意文が表示される
3. 「削除」を選択すると、タスクが削除され、DB（PostgreSQL）にも反映される。「キャンセル」を選択した場合は何も変更されない

### UC4: タスクを並び替える
1. 利用者は「未着手」カラム上部の「優先度順」ボタンをクリックし、カラム内のタスクを優先度の高い順に並べ替える
2. 並べ替え後、特定のタスクを一番上に置きたい場合は、そのタスクカードをドラッグ&ドロップで任意の位置に移動する（ソート状態は固定されないため自由に並び替えられる）
3. 「期限順」ボタンをクリックすると、期限が近い順（期限なしは末尾）に並べ替わる
4. 並び順はDB（PostgreSQL）に保存され、再読み込み後も維持される

## 8. 技術スタック

フロントエンドはReact + TypeScript + Vite + dnd-kit（Next.jsは対象外）、バックエンドはJava + Spring Boot、DBはPostgreSQLを使用する。
選定理由の詳細は [技術スタック](tech-stack.md) を参照。

## 9. 今後の拡張候補（MVP後）

- 複数ボード管理
- カラムの追加・削除・名称変更
- タスクの詳細拡張（ラベル・チェックリストなど）
- 複数端末からのアクセス（現状はローカル環境での起動を想定）
- ユーザー認証・複数人共有
- DnDのキーボード操作対応
